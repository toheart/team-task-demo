# Case 契约

## 场景边界

| 条件 | 组织方式 | 例子与边界 |
|---|---|---|
| 同一实体的自然状态推进 | 一个 `test()`，用 `test.step()` 标出关口 | 创建 → 保存 → 刷新回显；保存失败时，回显未获验证 |
| 身份、故障前置或预期终点不同 | 独立 `test()`，各自建数据和清理 | 管理员提交成功与普通用户被拒绝不共享同一草稿 |
| 相同规则的输入组合 | 下沉 Unit/App | 五种非法字段无需五次浏览器创建 |
| 同一断言在多条旅程重复 | 指定主要证明场景 | 列表可见性已由创建旅程证明，其他旅程仅保留必要检查 |

文件、Case ID、`test()` 不要求一一对应。一个 ID 对应多个具名场景时，结果必须定位到 Case ID、文件、完整测试名与环境；同 ID 的一个 PASS 不能掩盖另一个 FAIL。

## 覆盖映射

设计或合并场景前，在现有 `test-guides/e2e.md` 和 `test-evidence.md` 记录：

| 验收事实与来源 | 旅程 / 场景 | 最低有效层与系统层独有证明 | Case ID、文件和测试名 | dev / remote 断言范围 | 运行证据 / 未覆盖 |
|---|---|---|---|---|---|
| 例：刷新后仍显示新建对象，来自验收标准 AS-1 | 创建对象 / 保存回显 | App 验证持久化；System 验证 UI 创建与刷新回显 | 落地后填入实际名称 | dev 完整链路；remote 未配置时记 NOT_APPLICABLE | 分环境关联结果，未运行记 NOT_RUN |

合并或删除旧 Case 前，把每条独有断言映射到新场景或低层测试。资产存在只表示有测试；PASS 只证明该版本、环境和本次实际执行的断言。

## 每个 Case 的最小声明

- ID、稳定场景名、验收事实来源、起点和验收终点。
- dev 与 remote 的执行路径及各自断言范围。项目没有远程测试环境时，显式声明 `not-configured`；配置远程环境后再补该路径。登记不代表执行。
- 数据来源、目标资源、身份、是否写入、清理方式与失败时保留策略。只读 Case 可使用预置数据；写入 Case 要有自身 run ID 和明确的资源归属。
- UI 断言、真实请求或后端状态断言，以及需要时的外部副作用断言。Fake 副作用只证明 Fake 路径，不能冒充真实外部系统结果。

远程写入采用每次运行的 `E2E_REMOTE_CONFIRM=<CASE_ID>`。同一旅程若草稿与执行需要不同授权，应拆开登记，避免草稿授权覆盖执行。
