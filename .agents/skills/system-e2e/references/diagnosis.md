# 失败诊断契约

先读业务结果与 `case-id`、`resource-note`、`cleanup-failed` 注解，再读失败步骤、Trace、截图。按 run ID 和业务资源 ID 关联页面、真实请求、只读后端状态及外部副作用。页面可见成功消息但请求目标 ID 错误时，判为业务/可测性问题，不判 PASS。

| 现象 | 首查 | 边界 |
|---|---|---|
| 定位不唯一 | `data-testid` 是否同时挂在包装元素与按钮 | 修页面契约和组件测试；不要用 `.first()` 掩盖 |
| 页面成功但后端未变化 | 请求目标 ID、响应与刷新回显 | 不能只断言 toast |
| 共享资源冲突 | 并行 Case 的目标资源、run ID、清理范围 | run ID 不等于业务资源隔离 |
| 远程未授权或认证缺失 | 环境配置是否存在 | 记 NOT_RUN；不要要求用户在对话中粘贴凭据 |
| 清理失败 | 原始业务结果与清理错误分别记录 | 不用清理错误覆盖原始失败，也不能汇总通过 |

输出：环境与版本、Case ID/测试名、失败步骤、页面与后端状态、实际请求目标、外部副作用、资源清理状态、证据路径、确认的根因或待验证假设、最小修复与新 run 的复验结果。没有重跑时明确写未验证。
